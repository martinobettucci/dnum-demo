# SPEC-003 — Compte administrateur initial et secrets

Itération 002. Décisions : ADR-003 (secrets), ADR-012 (seed sans écrasement, amende ADR-003 sur la source de vérité
du mot de passe admin). Couvre CA-002-2, CA-002-4, CA-002-5, CA-002-33.

> **Amendement tour 3 (2026-11-17, préparation du gel `dev`)** : SPEC-003.5 amendé ; SPEC-003.10, 003.11, 003.12 nouvelles.
> **Révision tour 3 (même date, relevé `product-owner`)** : SPEC-003.10 et 003.11 vérifiés sans `deploy` ni `reset` (stub GoTrue local
> + `seed.py` direct, `GOTRUE_URL`) ; SPEC-003.12 n'a plus de [T]. Marqueurs : **[T]** automatique, **[P]** policy, **[R]** recette réelle (responsable applicatif).
> Motif : relevé DevOps, le seed réécrivait `ADMIN_PASSWORD` à chaque `deploy`, y compris avec données réelles.
> Après création, la base fait foi pour le mot de passe admin ; `ADMIN_PASSWORD` n'est plus qu'un mot de passe initial.
>
> **Amendement tour 4 (2026-11-17, ADR-013 D-4 à D-6)** : le premier `./dev deploy` après levée du gel est `./dev deploy service`.
> Les [R] de SPEC-003.10 et SPEC-003.12 (d) sont réécrits pour la pile `service` (sur `dev`, `reset` seulement après D4) ;
> le premier contrôle réel de `email_confirmed_at` est le second `deploy service` (SPEC-003.11, ADR-013 D-4).
